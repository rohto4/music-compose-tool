KASANE

曲の流れを触って、音にする。

結論：鼻歌AIではなく、洗練された「作曲楽器」を作る。

少数精鋭のHero Kitを最初から曲として鳴らし、sceneを選び、音楽的なmoveを同じ位置で比較する。AIと鼻歌は主画面・初回導線・完成条件から外す。

honest diagnosis

旧Phase 1は、壊れにくいが「曲を作り続けたくなる中心」が弱かった

  • 150 tests、15 browser journey、136 sound、46 chord、42 patternは、技術proofであって音楽的な喜びのproofではなかった。
  • 3入口、3制作段階、5 source tab、多数catalogが、曲より先にProductの分類を学ばせた。
  • 鼻歌は明確に歌えないと意図どおりのsymbolic melodyになりにくく、生成AIまでつないでも良い曲の再現性をProduct promiseにできなかった。
  • Web内でDAWを完成させようとし、Webが強い比較・capture・handoffへ集中できなかった。

残す：編集可能data、undo、即時試聴、portable handoff、安全境界。 捨てる：鼻歌前提、AI品質待ち、旧screen構成、件数競争。

where we attack

攻める場所を3つに絞る。鼻歌と生成AIは0%のprimary dependency

INTERACTION48曲の全体、現在位置、次の操作、結果が同じ視野にある。説明より直接操作。
CURATED SOUND37役割、voicing、groove、transition、mixを一つのHero Kitとして調律する。
DETERMINISTIC MUSIC15選んだmoveが毎回同じ範囲だけを変え、音楽的に成立する。

48 / 37 / 15はKPIではなく、初版で労力を配分する設計比重です。Humming / generative AIは将来optionであり、core loop・navigation・acceptance gateには含めません。

WHO
白紙DAWでは止まるが、loopを並べるだけでなく展開とmelodyへ自分の判断を残したい人。
PAIN
音色・patternを大量に探しても一曲として噛み合わず、鼻歌／AIは入力・出力の当たり外れが大きい。
SUCCESS
説明なしでKitを鳴らし、sceneを選び、moveを比較・採用して「良くなった」と耳で判断できる。
ANTI-GOAL
full DAW、prompt生成器、鼻歌精度競争、preset件数競争、AIによる自動完成。

技術基盤と、誇張しない境界
  • AudioWorkletをtransport / DSP候補とし、UI threadから音を分離する。
  • OPFSをworking setに使う候補とするが、site data消去に備えてportable snapshotを必須にする。
  • Project / HeroKit / Scene / Role / Clip / MoveRecipeを共通truthにする。
  • MIDI、WAV / stems、DAWprojectを同じsnapshotから生成する。
  • 実音質、browser latency、DAW importは実測前に完成と表現しない。AI品質をcore proofへ混ぜない。

source boundary

今回確認した一次資料

  • BandLab Studio — browser / mobile DAW workflow
  • Soundtrap — loops, instruments, effects, desktop latency claim
  • Ableton Learning Music — small ideasを直接組み合わせる学習体験
  • Spotify Basic Pitch — 1 instrumentで最も良く動く転写境界
  • Splice Create — compatible loop stackとDAW handoff
  • Output Arcade — theme別Line / curated Kit / Macro
  • MDN AudioWorklet — separate audio thread
  • MDN OPFS — local working storageと消去境界
  • DAWproject 1.0 — open ZIP / XML exchange format
